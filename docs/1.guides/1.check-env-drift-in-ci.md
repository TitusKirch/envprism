---
title: Check env drift in CI
description: Fail a CI run when committed .env files drift from the base — by value, or by keys only.
---

`envprism diff --check` prints nothing and sets the exit code: `0` when every
file matches the base, `1` otherwise. Decide first which kind of match you
need, because `--check` is stricter than it looks.

## What counts as drift

Every file is compared with the base — the file `--base` names, else
`.env.example`, else the first file found (the `base` config section changes
the fallbacks). A key drifts when it is
**missing** from a file, **extra** in a file, or its value **differs** from the
base. Placeholder values such as `CHANGEME` are flagged in the TUI but do not
count as drift.

So `--check` passes only when every file agrees with the base **value for
value**. That suits files meant to be identical. For the usual set — an example
file plus environments with their own values — check the keys instead (step 3).

::callout{type="warning" title="An empty comparison passes"}
With no `.env*` file found, or only one, there is nothing to compare and
`--check` exits `0`. In CI only committed files exist — a gitignored `.env` is
not there — so make sure the files you mean to compare are in the repository.
::

## Steps

1. **Choose what to scan.** With no argument envprism scans the working
   directory. Pass directories or files to scan those instead —
   `bunx envprism diff .env.example .env.ci --check` compares exactly two files —
   or set a default list in `discovery.paths` in `envprism.config.*`.

2. **Check values**, when the files should be identical:

   ```bash
   bunx envprism diff --check
   ```

   The failure code can be changed with `diff.checkExitCode` in the config.

3. **Check keys only**, when values are allowed to differ. The JSON report
   carries a state per key and file; fail on `missing` (add `"extra"` to also
   catch keys the base does not declare):

   ```bash
   bunx envprism diff --json \
     | jq -e '[.files[].keys[] | select(. == "missing")] | length == 0'
   ```

4. **Run it in the pipeline.** envprism needs Bun, not Node:

   ```yaml
   - uses: oven-sh/setup-bun@v2
   - run: bunx envprism diff --check
   ```

5. **Run it before a commit**, optionally, with the same command in your
   pre-commit hook.

## Checklist

- [ ] The files to compare are committed, and at least two of them are found.
- [ ] The base is the file you expect (`.env.example`, or `--base`).
- [ ] The check matches the intent: `--check` for identical values, the `jq`
      filter for matching keys.
- [ ] The CI job installs Bun before calling `bunx envprism`.
- [ ] A deliberately removed key makes the job fail.
